# 基金交易日历与确认日查询工具

## 运行说明

要求 Python 3.10 或更高版本，仅使用 Python 标准库，不需要安装第三方依赖。

在项目目录执行：

```powershell
cd code
py -3 app.py
```

浏览器访问 <http://127.0.0.1:8000/>。

服务启动时会一次性加载并校验境内和美股交易日历，构建内存交易日列表和共同交易日列表。日历文件缺失、编码错误、CSV 表头或行格式错误、日期重复、日期断档、交易标记错误或范围不完整时，服务拒绝启动。查询过程中不会重新扫描 CSV。

运行时会在 `code/queries.sqlite3` 创建 SQLite 历史库；该文件是运行产物，不需要随源代码提交。

## 功能与接口

- `POST /api/query`：单笔计算。请求体为 `{"submit_time":"YYYY-MM-DD HH:MM","fund_type":"EQ|BD|QDII"}`。
- `POST /api/batch`：批量计算。请求体为 `{"items":[...]}`，结果顺序与输入一致并保留 `apply_id`；单条错误不会影响其他条目。
- `GET /api/calendar?date=YYYY-MM-DD&market=A_SHARE|US`：返回指定日期是否交易日及下一个交易日。
- `GET /api/history?limit=50`：返回最近查询记录，`limit` 范围为 1 至 500。
- `GET /api/health`：返回服务健康状态。

成功响应统一为：

```json
{"success":true,"data":{},"error":null}
```

非法输入返回 HTTP 400 和 `INVALID_INPUT`；未知 API 路径或静态资源返回 HTTP 404 和 `NOT_FOUND`；服务内部异常返回 HTTP 500 和统一 JSON 错误，不返回 HTML 错误页。

单笔结果包含 `T_date`、`confirm_date`、`query_date` 和 `reasons`。页面只展示 API 返回的日期和判断依据，不在浏览器端复制日期计算逻辑。

## 日期规则

- 境内交易日 `15:00`（含）前提交：当天为 T 日。
- 境内交易日 `15:01` 以后提交：顺延到下一个境内交易日。
- 周末或节假日提交：顺延到下一个境内交易日；不会因为非交易日和超时规则而重复顺延。
- EQ、BD：确认日为 T 日之后第 1 个境内交易日（T+1，不包含 T 日）。
- QDII：T 日和确认日必须是境内与美股共同交易日；确认日先取 T 日之后第 2 个境内交易日（T+2，不包含 T 日），若美股休市则顺延到下一个共同交易日。
- 查询日是确认日之后的第一个境内交易日，严格晚于确认日。

确认日偏移量和市场要求位于 `config.json`，日历文件位于 `data/`。

## 产品设计说明

目标用户是基金客服和运营人员，以及需要批量提交申请的渠道或运营系统。单笔页面提供提交时间和基金类型选择，展示 T 日、确认日、查询日及逐步判断依据，帮助客服解释日期来源；历史区域用于追溯请求、结果和错误。批量 API 供上游系统一次提交多条申请，保留 `apply_id`，便于对账和定位单条失败记录。

页面增强功能选择为历史记录展示和 API 批量能力：前者减少客服重复查询并提供留痕，后者降低渠道系统逐条调用的成本。所有日期计算集中在服务端引擎，页面只负责输入、展示和历史读取。

## 性能实测

在本项目当前 Python 3.12.6 环境中，使用内存交易日列表、共同交易日列表和二分定位，逐条计算 `batch_test.csv` 的 100000 条数据并与参考答案比较：

- 计算条数：100000；
- 结果匹配：100000/100000；
- 实测耗时：本次干净目录复现为 1.891 秒（此前多次实测约 1.6–2.1 秒）；
- 题目要求：小于 5 秒；
- 结论：满足性能要求。

该数字是日期计算引擎的批量实测，不包含启动时加载日历的时间；HTTP 层也复用同一个已加载引擎。

## 自测题答案

1. **某周五 15:00 整提交股票基金申购，T 日是哪天？若 15:01 提交呢？** 15:00（含）前提交，T 日是当天周五；15:01 已超过截止时间，T 日顺延到下一个境内交易日，通常是下周一（如果下周一也是非交易日，则继续顺延到其后的第一个境内交易日）。
2. **周六上午提交申请，与同一周周五 15:30 提交申请，两者的 T 日是否相同？为什么？** 通常相同，都是下一个境内交易日。周六本身不是交易日，周五 15:30 又超过了 15:00 截止时间；两种情况都不能归属周五或周六，因此都顺延到下周一（或下一个实际境内交易日）。
3. **一只 QDII 基金，境内算出的申请日恰逢美股休市，应如何处理？确认日呢？** 申请日（T 日）必须是境内与美股共同交易日；如果按境内日历得到的候选 T 日美股休市，就顺延到下一个共同交易日。确认日先从调整后的 T 日起按境内交易日计算 T+2（不包含 T 日）；如果这个 T+2 候选日美股也休市，再顺延到下一个境内与美股共同交易日。QDII 的 T 日和确认日都不能只使用境内交易日历。

## AI 输出错误修正说明

实现和验收过程中重点核对并固定了以下规则：

- 将 `15:00` 明确定义为包含边界，`15:01` 才顺延；
- T+N 的计数不包含 T 日；
- 非交易日直接寻找下一个交易日，不能再额外增加一天；
- QDII 的 T 日和确认日都必须检查境内与美股共同交易日；
- 查询日必须取确认日之后的第一个境内交易日，不能等于确认日；
- 批量单条错误改为统一错误对象，确保错误不影响其他条目；
- 未知 POST 路径在读取请求体前直接返回 HTTP 404；
- 日历 CSV 启动校验覆盖缺失、编码、CSV 格式、表头、行字段、重复、断档和范围错误。
